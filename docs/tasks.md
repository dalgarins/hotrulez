# hotrulez Tasks — 0.8 (Authoring Polish)

Status: draft
Last updated: 2026-07-03
Source: `docs/spec.md` (0.8 — Authoring Polish).
Predecessor: `docs/v3/tasks.md` (archived; the 0.7 Actionable Diagnostics

This list breaks out the **0.8 — Authoring Polish** milestone in full: a
structure view, code folding, quick documentation, and parameter info — four
read-only authoring surfaces over the PSI and data the plugin already owns. The
later milestone (0.9 Toward Semantics) is a roadmap sketch, not 0.8 scope, and is
not broken into checkable items — one milestone per release.

Coverage status (as of 2026-07-03): nothing below is started. All PSI nodes the
features consume are already generated by the grammar; all dialect/vocabulary
data (`RulesService`, `FirebaseRulesBuiltins`) and the resolver
(`FirebaseRulesScopes`, `FirebaseRulesReference`) shipped in 0.5–0.7. 0.8 adds
view/EP layers plus one new doc-prose table on top.

## Milestone 0.8: Authoring Polish

### Shared doc-prose table

- [ ] Add `dev.lezli.hotrulez.documentation.FirebaseRulesDocs`: a static,
  doc-sourced map from each documentable entity to `(title, summaryHtml, docUrl)`,
  keyed off the *same* keys `RulesService.members` / `FirebaseRulesBuiltins` use
  (member paths like `request.auth`; operation/global/helper/type names).
- [ ] Populate entries for: `allow` operations; built-in globals
  (`request`/`resource`/`firestore`); Firestore + Storage members; path helpers
  and cross-service helpers; type/global namespaces & conversion functions.
- [ ] Mark namespace *members* (`math.abs`, `timestamp.date`, …) `UNCONFIRMED` /
  deferred — enumerate only what the docs confirm.
- [ ] Each entry cites its Firebase doc page (used by `getUrlFor`).

### Feature 1 — Structure view

- [ ] Add package `dev.lezli.hotrulez.structureview` with
  `FirebaseRulesStructureViewFactory` (`lang.psiStructureViewFactory`),
  `FirebaseRulesStructureViewModel` (`StructureViewModelBase`, root =
  `FirebaseRulesFile`), and `FirebaseRulesStructureViewElement`
  (`StructureViewTreeElement`, `NavigatablePsiElement`).
- [ ] Build children from typed PSI: service → block (matches / allows /
  functions); match → block; top-level match/function; functions nested in
  matches. `function`/`allow` are leaves.
- [ ] Presentation: service name; match path; `fn(params)`; `allow ops`. Reuse
  platform `AllIcons.Nodes.*` icons (no new assets). Do **not** surface
  `let`/`return`/path variables.
- [ ] Offer `Sorters.ALPHA_SORTER` (source order default); wire
  `getSuitableClasses` for navigation-bar / "select in" support.
- [ ] Null-safe: a partially-parsed file yields a partial tree, never an exception.
- [ ] Register `lang.psiStructureViewFactory` in `plugin.xml`.

### Feature 2 — Code folding

- [ ] Add package `dev.lezli.hotrulez.folding` with `FirebaseRulesFoldingBuilder`
  (`FoldingBuilderEx`, `DumbAware`).
- [ ] Emit `FoldingDescriptor`s over the braces `{…}` of a `service` block, a
  `match` block, and a `function` body, plus `BLOCK_COMMENT` tokens — folding only
  the braces so the service name / match path stays visible.
- [ ] Placeholder text `{…}` for blocks, `/*…*/` for block comments;
  `isCollapsedByDefault` = `false` everywhere.
- [ ] Guard against unclosed/empty blocks (emit only when both braces present and
  interior non-empty) so an in-progress edit produces no bogus/zero-length fold.
- [ ] Register `lang.foldingBuilder` in `plugin.xml`.

### Feature 3 — Quick documentation

- [ ] Add package `dev.lezli.hotrulez.documentation` with
  `FirebaseRulesDocumentationProvider` (`AbstractDocumentationProvider`).
- [ ] User symbols (resolved via the shipped resolver): function → `function
  name(params)` + preceding line/block comment; parameter → `parameter 'x' of
  function f`; `let` → `let x = <expr>`; path/recursive wildcard → `path variable
  'x' captured by match /…`.
- [ ] Built-in vocabulary from `FirebaseRulesDocs`, dialect-aware via
  `RulesService.forElement`: `allow` operation; built-in global; member on a
  `member_expression` (keyed by the shared `receiverKey` path); path/cross-service
  helper; type/global namespace.
- [ ] `getUrlFor` returns the entity's Firebase docs URL (open-in-browser).
- [ ] `getCustomDocumentationElement` / `getDocumentationElementForLookupItem` so
  hover works on member identifiers and on completion lookup items.
- [ ] Return `null` (no fabrication) for unknown members / unresolved names.
- [ ] Register `lang.documentationProvider` in `plugin.xml`.

### Feature 4 — Parameter info

- [ ] Add package `dev.lezli.hotrulez.parameterinfo` with
  `FirebaseRulesParameterInfoHandler`
  (`ParameterInfoHandler<FirebaseRulesArgumentList, …>`).
- [ ] Trigger inside a `FirebaseRulesArgumentList`; resolve the callee
  (`FirebaseRulesCallExpression.expression`):
  - [ ] `reference_expression` → user `FirebaseRulesFunctionDeclaration`: param
    names from its parameter list;
  - [ ] bare helper (`get`/`exists`/`getAfter`/`existsAfter` via
    `RulesService.bareHelpersFor`) → single `path` param;
  - [ ] `member_expression` `firestore.get`/`firestore.exists`
    (`RulesService.CROSS_SERVICE_HELPERS`) → single `path` param.
- [ ] Highlight the current parameter by comma index (`updateParameterInfo` →
  `updateUI`); helper signatures may append the `FirebaseRulesDocs` one-liner.
- [ ] Do **not** offer signatures for global-namespace functions (deferred,
  `UNCONFIRMED` arity); do **not** validate arity.
- [ ] Register `codeInsight.parameterInfo` in `plugin.xml`.

### Shared correctness (must hold across features)

- [ ] Dialect-awareness: members/helpers key on `RulesService.forElement`
  (Firestore vs Storage; union in neutral files), matching completion.
- [ ] Scope-based resolution: doc/parameter-info callee lookup goes through
  `FirebaseRulesScopes` / `FirebaseRulesReference`, never a textual heuristic
  (forward references still document and still show parameters).
- [ ] Extract the completion contributor's `receiverKey` member-path logic to a
  shared helper if both completion and documentation consume it (no duplication).

## Release-Quality Acceptance (0.8)

- [ ] Structure tool window shows the service → match → function/allow outline
  with correct labels, navigation, and alpha-sort, for both dialects; graceful on
  malformed input.
- [ ] Service/match/function braced blocks and block comments fold, heads visible.
- [ ] Quick docs show doc-grounded prose + external Firebase link for
  operations/built-ins/dialect-correct members/helpers, and signature/comment for
  user functions/parameters/`let`s/path variables; nothing for unknown members or
  unresolved names.
- [ ] Parameter info shows + highlights signatures for user-function calls and
  fixed-arity path helpers; nothing for out-of-scope calls; never validates arity.
- [ ] All v1/v2/0.7 non-goals still hold; nothing connects to Firebase, evaluates
  authorization, or infers a type.
- [ ] Tests cover all four features (positives, dialect-awareness, recovery) and
  the doc-table integrity check.
- [ ] Implementation choices follow current official JetBrains SDK and Firebase
  docs.
